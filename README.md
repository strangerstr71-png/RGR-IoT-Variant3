# РГР з дисципліни «Інформаційні технології Internet of Things»

## Варіант №3 — Локальна метеостанція

Проєкт реалізує навчальну симуляцію локальної IoT-метеостанції з обробкою даних на периферійному пристрої (Edge Computing), локальним збереженням у SQLite, стисненням даних, передаванням до Firebase Realtime Database та подальшим аналізом у Google Colab.

**Важливо:** використано синтетичні метеорологічні дані, а не показники фізичних датчиків.

## 1. Мета роботи

Розробити програмну модель локальної метеостанції, яка забезпечує:

- Генерацію метеорологічних даних.
- Імітацію пропусків та аномальних показників.
- Очищення та перевірку даних.
- Збереження результатів у реляційній базі SQLite.
- Аналіз і візуалізацію метеорологічних показників.
- Порівняння алгоритмів стиснення gzip, zlib і bzip2.
- Передавання даних до Firebase та перевірку їх отримання.
- Статистичний аналіз у Google Colab.

## 2. Метеорологічні показники

Моделюються чотири параметри:

1. Швидкість вітру — м/с.
2. Температура повітря — °C.
3. Кількість опадів — мм.
4. Сонячна радіація — Вт/м².

Період моделювання: **2025 рік, 365 діб**.

Загальна кількість вимірювань: **1460**.

## 3. Локальна обробка даних

Основна програма: `variant3_iot.py`.

Програма генерує початкові дані, моделює пропущені та некоректні значення, виконує очищення і формує результати.

Отримані файли:

- `raw.csv` — початкові дані.
- `clean.csv` — очищені дані.
- `cleaning_audit.csv` — результати контролю очищення.
- `weather.sqlite` — реляційна база даних.
- `summary.csv` — статистичні показники.
- `run_report.json` — звіт виконання.
- `compression.json` — порівняння алгоритмів стиснення.

## 4. Стиснення даних

Порівнюються алгоритми:

- gzip;
- zlib;
- bzip2.

Стиснення застосовується до однакових JSON-даних. Результати порівняння зберігаються у `compression.json`.

У репозиторії також представлений стиснений файл `payload.json.bz2`.

## 5. Firebase Realtime Database

Для хмарного збереження використано Firebase Realtime Database.

Програма: `firebase_admin_upload_rgr3.py`.

У власному середовищі виконано передавання даних до Firebase та їх повторне отримання для перевірки.

Результати перевірки:

- `FIREBASE UPLOAD OK`
- `FIREBASE DOWNLOAD VERIFY OK`
- Кількість діб: 365.
- Кількість вимірювань: 1460.

Шлях даних у Firebase: `rgr_variant3_weather_2025`.

Підсумок перевірки збережено у `firebase_verified.json`.
### Передавання оптимізованого набору даних

Для зменшення обсягу переданих даних використано алгоритм bzip2. Стиснений файл payload.json.bz2 розміром 4799 байтів закодовано у base64 та завантажено до Firebase Realtime Database за допомогою скрипта firebase_optimized_bz2.py.

Шлях збереження: rgr_variant3_weather_2025_optimized.

Після завантаження виконано контрольне зчитування, декодування base64, розпакування bzip2 та перевірку цілісності даних за SHA-256.

Результати:
- FIREBASE BZIP2 UPLOAD OK
- FIREBASE BZIP2 DOWNLOAD VERIFY OK
- 365 діб
- 1460 вимірювань
- roundtrip_verified: true

Результат перевірки збережено у firebase_bz2_verified.json.
**Безпека:** приватний JSON-ключ сервісного акаунта Firebase не входить до репозиторію. Для повторного запуску необхідно використовувати власні облікові дані з відповідними правами доступу.

## 6. Google Colab

Ноутбук: `RGR_Variant3_Firebase_Colab.ipynb`.

У Google Colab виконано отримання даних із Firebase, статистичний аналіз, побудову графіків сезонних розподілів і лінійних трендів.

Отримані показники:

| Показник | Результат |
|---|---:|
| Середня швидкість вітру | 5,95 м/с |
| Середня температура | 12,19 °C |
| Сума опадів | 1208,83 мм |
| Середня сонячна радіація | 363,80 Вт/м² |

### Лінійні тренди протягом модельного року

| Показник | Нахил тренду за добу |
|---|---:|
| Температура | −0,01102 °C |
| Швидкість вітру | +0,00067 м/с |
| Опади | +0,00068 мм |
| Сонячна радіація | −0,22389 Вт/м² |

Ці значення характеризують лише синтетичний набір за один модельний рік і не є доказом довгострокових кліматичних змін.

## 7. Порівняння з кліматичними нормами Одеси

Додатково виконано порівняння модельних місячних температур та сум опадів із довідковими кліматичними нормами Одеси.

Розраховано місячні відхилення та побудовано графік `odesa_climate_comparison.png`.

Найбільше позитивне температурне відхилення в модельних даних: **+7,01 °C у квітні**.

Найбільше негативне температурне відхилення: **−4,89 °C у листопаді**.

Це порівняння демонструє методику аналізу відхилень, а не фактичні метеорологічні аномалії 2025 року.

## 8. Візуалізація

У репозиторії представлені:

- `weather_timeseries_corrected.png` — часові ряди чотирьох метеопоказників.
- `weather_seasons_colab.png` — сезонні розподіли.
- `weather_trends_colab.png` — лінійні тренди.
- `odesa_climate_comparison.png` — порівняння з кліматичними нормами Одеси.

## 9. Структура проєкту

- `variant3_iot.py` — генерація, очищення та локальний аналіз даних.
- `firebase_admin_upload_rgr3.py` — передавання даних у Firebase та перевірка.
- `RGR_Variant3_Firebase_Colab.ipynb` — хмарний аналіз у Google Colab.
- `weather.sqlite` — локальна база даних.
- `README.md` — документація проєкту.
- CSV, JSON, BZ2 та PNG — результати експерименту.

Для локального запуску потрібен Python і бібліотеки, які використовуються у вихідному коді. Для роботи з Firebase необхідні власний приватний ключ сервісного акаунта та адреса відповідної бази даних.

## 10. Висновок

У межах РГР реалізовано повний навчальний цикл обробки даних IoT: від генерації показників чотирьох віртуальних метеодатчиків і локального очищення до збереження в SQLite, стиснення, передавання у Firebase та статистичного аналізу в Google Colab.

Практична робота демонструє можливості Edge Computing, хмарного зберігання й аналітики для систем моніторингу навколишнього середовища.
