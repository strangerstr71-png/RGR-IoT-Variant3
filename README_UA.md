# РГР IoT — варіант №3. Локальна метеостанція

Проєкт формує **синтетичні** щоденні метеодані за 2025 рік (365 діб) за чотирма каналами: вітер, температура, опади, сонячна радіація. Немає фізичних датчиків; це навчальна симуляція. Скрипт зберігає сирі/очищені дані, аудит очищення, 1460 реляційних вимірювань SQLite, статистику, графіки та порівняння gzip/zlib/bzip2 для ідентичного JSON.

## 1. Локальний запуск

Установи Python 3.10+ і відкрий термінал у теці проєкту:

```powershell
python -m pip install -r requirements.txt
python variant3_iot.py
```

Далі відкрий папку `rgr3_assets`. Перевір `raw.csv`, `clean.csv`, `weather.sqlite`, `summary.csv`, `cleaning_audit.csv`, `compression.json`, `timeseries.png`, `seasons.png`, `correlation.png`, `trend.png` та `payload.json`.

**Скриншот №1:** термінал із рядком `LOCAL RUN OK`. **Скриншот №2:** вміст теки `rgr3_assets`. **Скриншот №3:** графіки та `compression.json`.

## 2. Firebase Realtime Database — робиться у власному обліковому записі

1. Відкрий https://console.firebase.google.com/ і створи проєкт або вибери власний.
2. Обери **Build → Realtime Database → Create Database**; вибери регіон та правила доступу. Залиш правила **приватними**, не встановлюй глобальні `.read: true` / `.write: true` для захищених даних.
3. У Realtime Database скопіюй **саме Database URL** (`https://<...>.firebasedatabase.app` або регіональне `https://<...>.firebaseio.com`). Не плутай із Firebase Console URL.
4. Отримай авторизований короткоживучий Firebase **ID token** для користувача, якому правила дають читання/запис. Використовувати облікові дані сервісного акаунта в чаті чи відкритому GitHub **не можна**. `firebase_sync.py` очікує токен у змінній `FIREBASE_AUTH`.
5. У PowerShell задай тимчасові змінні у **поточному вікні** (не роби скриншот з токеном):

```powershell
$env:FIREBASE_URL="https://YOUR-DB-URL.firebasedatabase.app"
$env:FIREBASE_AUTH="YOUR_SHORT_LIVED_ID_TOKEN"
python firebase_sync.py
```

6. Очікуваний успіх після реально виконаного PUT і GET: `Firebase PUT: HTTP 200` і `Firebase GET OK; retrieved days=365 measurements=1460`. Зберігай **скриншот із термінала без токена** та скриншот дерева `rgr_variant3_weather_2025` у Firebase Console.

**Важливо:** без дійсного Firebase URL і авторизованого токена синхронізація **не виконується**. У комплекті є тільки перевірений локальний запуск, а не вигаданий доказ хмарного підключення.

## 3. Google Colab — перевірка зворотного завантаження

1. Відкрий https://colab.research.google.com/ → Upload notebook → вибери `RGR_Variant3_Firebase_Colab.ipynb`.
2. Виконуй клітинки послідовно. У третій клітинці введи Database URL, а токен — у приховане поле `getpass`.
3. Після реального GET з Firebase мають з'явитися 365 записів, статистика, лінійні графіки й кореляції.
4. **Скриншоти №4–5:** результат GET з Firebase і статистика/графіки в Colab, на яких не видно секретів.

## 4. GitHub

Створи новий репозиторій, наприклад `rgr-iot-variant3-weather`, та завантаж файли `variant3_iot.py`, `firebase_sync.py`, `RGR_Variant3_Firebase_Colab.ipynb`, `requirements.txt`, `README_UA.md`, `.gitignore`. За бажанням додай приклад `summary.csv`, графіки та анонімізовані результати. **Ніколи** не публікуй токени або приватні ключі. Збережи URL репозиторію та додай його до РГР.

## 5. Що долучити до звіту

- Робочий код `.py` та ноутбук `.ipynb`, ZIP цього проєкту.
- Скриншоти локального запуску, SQLite/графіків, перевіреного Firebase PUT/GET, результатів у Colab.

- Підсумковий опис досліду з фактичними числами саме з твого запуску.

## Попередні результати локального запуску

У контрольному запуску `seed=2026` сформовано 365 діб, 4 канали та 1460 вимірювань. Для кожного каналу вставлено по 8 пропусків і 4 позадіапазонні значення; всі усунуті очищенням. `compression.json` містить точні розміри і SHA256 контрольного набору. Числа можуть відрізнятися від попередньої чернетки РГР, оскільки вони отримані поточною реалізацією. Не приписуй програмі роботу з Firebase чи Colab до власного фактичного виконання.
